## Before using this in the product

1. Review the visual identity on real screens. The team needs to choose a default from the supported Blue and Green themes and assign design and engineering owners.
2. Connect each screen to the shared API layer. Stories use local data and MSW examples; the server must validate data, enforce permissions and handle business transitions.
3. Decide the Q18 conversation channel, Q19 payouts, Checkout hold/abandonment rules and answer-editing policy. The catalogue shows the relevant UI states, but these policies are still open.
4. Test authenticated flows with persisted data and review accessibility on every completed page. Unit coverage and sampled keyboard, contrast and responsive checks cover the library, not the full application.
5. Assign an owner, review token/API changes and record migration notes before wider use. External publication and synchronization require explicit approval.

Accessibility follow-up: the open Select popup needs a screen-reader review in its host page. Its browser keyboard scenario passes, but a standalone automated scan flags focusable content inside the hidden preview background. That finding remains documented for review.

The design system includes mentor ratings and reviews,
as requested on 7 September 2026. Demo feedback is fictional. No real reviews
have been published, and there is no production review service.

The searchable mentor catalogue is a local design extension requested on
7 September 2026. It goes beyond the original no-search brief in R13/D21 and
issue #20. It filters supplied data; production search, data access and the
release decision still need implementation and agreement.

Video, subscriptions, public session notes and unrelated dashboard widgets remain
outside the current design-system scope. A public mentor review is distinct from
a private session note.

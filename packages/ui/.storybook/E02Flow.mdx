# E02 mentors become bookable

Start at [the invitation](/prototypes/devmentor-journey/index.html#s26), sign in,
accept it, then complete the mentor setup. This page maps stories #15–19 to the
shared UI and the connected prototype. The [handoff entrypoint](?path=/docs/design-system-implementation-handoff--docs)
also covers E01 and links every story to its source.

The prototype simulates invitation, save and Stripe responses in the browser.
Reloading resets demo business data. It creates no real mentor account, sends no
invitation and changes no payout account. Its UI/prototype specification is
`.ai/specs/2026-09-09-e02-design-handoff.md`. Production architecture and contracts
are specified in `.ai/specs/2026-09-08-mentors-become-bookable.md` and its story
specifications, already present in this repository. The prototype README links
all five story specifications, including Connect for iteration 1.1.

## Invitation to first bookable session

1. Open [Invitation, s26](/prototypes/devmentor-journey/index.html#s26) while signed
   out. Continue to sign-in, using a mentee demo account from **Auth scenarios**
   or a new verified email account. Successful authentication returns to the
   invitation.
2. Accept the invitation. The mentor role is added to the account's existing
   roles. [Mentor workspace, s11](/prototypes/devmentor-journey/index.html#s11)
   shows the setup checklist and a deadline 14 days after acceptance for the
   profile, both prices and first bookable time.
3. Open [Edit mentor profile, s27](/prototypes/devmentor-journey/index.html#s27).
   Add a display name, a link to public work, a description and stack tags. Save,
   then publish the profile and open its public page.
4. Set both session prices in the mentor workspace: 25 minutes within
   PLN 90–600 and 50 minutes within PLN 180–1,200. These values are demo operator
   settings. The application will supply the current bounds.
5. Publish a future time in the displayed timezone. Open the public profile and
   choose a session to see the same saved prices and available time. Open the profile editor to copy the
   local public-preview link.
6. Open [Payout settings, s28](/prototypes/devmentor-journey/index.html#s28) to
   review the separate Connect flow. Its production release remains iteration
   1.1; it does not block this demo's first-iteration setup checklist.

For the existing public sample mentor, sign in as Alex using **Auth scenarios**.
Other mentors and newly invited accounts have their own setup state. Signing in
as another account must not reveal or overwrite someone else's draft profile.

Choose **Mentor scenarios** in the review toolbar to open **Mentor demo
controls**. **Invitation link** selects Valid, Expired, Unknown or Already used;
**Open invitation** opens s26. **Fail the next mentor request** selects a failure
for one request. On s29, **Return status** selects the four Connect responses;
**Return to DevMentor** applies the result and opens payout settings.
**Refresh payout status** retries a status request on s28.

Clipboard failure uses the browser's denied or unavailable clipboard response;
it has no separate demo selector. In an isolated browser check, deny clipboard
write access or have `navigator.clipboard.writeText` reject, then choose
**Copy profile link**. The link stays selectable for manual copying. Restore the
browser fixture after that check.

Scenario controls are review tools, separate from the product navigation.
Failure selection affects a local request; it does not imitate a running server,
real cooldown or provider callback. Every protected direct link still uses the
current demo account.

## Product decisions retained in the handoff

Reviews, ratings and search remain in the design as requested. Older references
in #16 and #20 still say no ratings or search; the accepted production
specification must record that change. The examples use fictional reviews and
local catalogue data. No review eligibility, moderation or search backend is
implemented here.

Invitation creation and sending belong to E05. E02 starts from a received link.
Production work includes token expiry and single use, verified-account binding,
role/session updates, mentor ownership, public-profile queries, URL validation,
timezone conversion, conflict/booking locks, authoritative price rules, payment
effects and Connect webhooks. The UI prototype illustrates the results and
recovery paths; it does not provide those services.
